## Task 1: models

- `Film.language` is a many-to-one relationship through `language_id`. `film` has two foreign keys to `language` (`language_id` and `original_language_id`), so `foreign_keys=[language_id]` tells SQLAlchemy which one this relationship uses.
- `Film.actors` / `Actor.films` and `Film.categories` / `Category.films` are many-to-many relationships with `secondary="film_actor"` and `secondary="film_category"`, linked with `back_populates`.
- `FilmActor` and `FilmCategory` are also mapped as classes with a composite primary key, because they're real tables (with `last_update`) and the queries of task 2 join them directly.
- Only the columns the exercise needs are mapped. `fulltext` (`tsvector`) and `special_features` (`text[]`) are left out, which is fine because the models are only used to read. `rating` is a PostgreSQL enum (`mpaa_rating`) and is read as a string.

### Q1: number of films per category

ORM code:

```python
films = func.count().label("films")
select(Category.name, films)
    .join(FilmCategory, FilmCategory.category_id == Category.category_id)
    .group_by(Category.category_id, Category.name)
    .order_by(films.desc(), Category.name)
```

| Handwritten | Generated by the ORM (`echo=True`) |
|---|---|
| `SELECT c.name, count(*) AS films`<br>`FROM category c JOIN film_category fc ON fc.category_id = c.category_id`<br>`GROUP BY c.category_id, c.name`<br>`ORDER BY films DESC, c.name` | `SELECT category.name, count(*) AS films`<br>`FROM category JOIN film_category ON film_category.category_id = category.category_id`<br>`GROUP BY category.category_id, category.name`<br>`ORDER BY films DESC, category.name` |

**Differences:** none in the logic. The ORM uses the full table names instead of the aliases `c` and `fc`. The label `films` becomes `AS films` and can be reused in `ORDER BY`, just like in the handwritten SQL.

### Q2: films longer than the average film

ORM code:

```python
avg_length = select(func.avg(Film.length)).scalar_subquery()
select(Film.film_id, Film.title, Film.length)
    .where(Film.length > avg_length)
    .order_by(Film.length.desc(), Film.film_id)
```

| Handwritten | Generated by the ORM |
|---|---|
| `SELECT f.film_id, f.title, f.length`<br>`FROM film f`<br>`WHERE f.length > (SELECT avg(length) FROM film)`<br>`ORDER BY f.length DESC, f.film_id` | `SELECT film.film_id, film.title, film.length`<br>`FROM film`<br>`WHERE film.length > (SELECT avg(film.length) AS avg_1 FROM film)`<br>`ORDER BY film.length DESC, film.film_id` |

**Differences:** the scalar subquery is the same. The ORM gives the aggregate an automatic label (`avg_1`) and qualifies `film.length` inside the subquery. Both refer to the inner `film`, so the meaning is the same. In more complex cases this is where you have to be careful that the subquery isn't accidentally *correlated* with the outer query. `scalar_subquery()` makes it independent here.

### Q3: the 10 actors with most films

ORM code:

```python
films3 = func.count().label("films")
select(Actor.actor_id, Actor.first_name, Actor.last_name, films3)
    .join(FilmActor, FilmActor.actor_id == Actor.actor_id)
    .group_by(Actor.actor_id)
    .order_by(films3.desc(), Actor.actor_id)
    .limit(10)
```

| Handwritten | Generated by the ORM |
|---|---|
| `SELECT a.actor_id, a.first_name, a.last_name, count(*) AS films`<br>`FROM actor a JOIN film_actor fa ON fa.actor_id = a.actor_id`<br>`GROUP BY a.actor_id`<br>`ORDER BY films DESC, a.actor_id`<br>`LIMIT 10` | `SELECT actor.actor_id, actor.first_name, actor.last_name, count(*) AS films`<br>`FROM actor JOIN film_actor ON film_actor.actor_id = actor.actor_id`<br>`GROUP BY actor.actor_id`<br>`ORDER BY films DESC, actor.actor_id`<br>`LIMIT %(param_1)s::INTEGER` |

**Differences:** the `LIMIT` value is sent as a **bound parameter** (`%(param_1)s` = 10) instead of being written into the SQL. The ORM does this for every literal value, which is also what protects it from injection. Grouping only by `actor.actor_id` works in both, because PostgreSQL knows `first_name` and `last_name` depend on the primary key.

## Task 3: N+1

`n_plus_one.py` loads the first 100 films by `film_id` and prints each title with its actors through `film.actors`. The `SELECT` statements are counted with the event listener in `db.py`.

Output (first and last lines):

```
   1 ACADEMY DINOSAUR: PENELOPE GUINESS, CHRISTIAN GABLE, LUCILLE TRACY, SANDRA PECK, JOHNNY CAGE, MENA TEMPLE, WARREN NOLTE, OPRAH KILMER, ROCK DUKAKIS, MARY KEITEL
   2 ACE GOLDFINGER: BOB FAWCETT, MINNIE ZELLWEGER, SEAN GUINESS, CHRIS DEPP
   3 ADAPTATION HOLES: NICK WAHLBERG, BOB FAWCETT, CAMERON STREEP, RAY JOHANSSON, JULIANNE DENCH
...

SELECT statements with lazy loading (N+1): 101
SELECT statements with selectinload:       2
```

**Before (N+1): 101 queries.** One query loads the 100 films:

```sql
SELECT film.film_id, film.title, ... FROM film ORDER BY film.film_id LIMIT %(param_1)s::INTEGER
```

Then, because `film.actors` is lazy-loaded by default, the first time each film's `actors` is read SQLAlchemy runs **one more query for that film**. That's 100 times:

```sql
SELECT actor.actor_id, actor.first_name, actor.last_name, actor.last_update
FROM actor, film_actor
WHERE %(param_1)s::INTEGER = film_actor.film_id AND actor.actor_id = film_actor.actor_id
ORDER BY actor.actor_id
```

**After (fixed, in a new session): 2 queries.** With `.options(selectinload(Film.actors))`, the ORM runs the same first query, then **one** query for the actors of all 100 films at once:

```sql
SELECT film_actor.film_id, actor.actor_id, actor.first_name, actor.last_name, actor.last_update
FROM film_actor JOIN actor ON actor.actor_id = film_actor.actor_id
WHERE film_actor.film_id IN (%(primary_keys_1)s::INTEGER, ..., %(primary_keys_100)s::INTEGER)
ORDER BY actor.actor_id
```

It then puts each actor in the right film's list in Python. The fix uses a new session, so the actors already loaded by the first part aren't reused from the session's identity map, which would hide the real number of queries.

I chose `selectinload` rather than `joinedload` because `actors` is a collection. `joinedload` would repeat each film's columns once per actor (a film with 10 actors comes back as 10 rows) and, combined with `LIMIT`, needs a subquery. `selectinload` keeps the 100 films in one simple query and the actors in another.
